# Product principles

## 1. Mission state outlives conversation

Mission is the durable product object. Conversation explains and collaborates; it does not own execution, evidence, plans, checkpoints, or completion.

## 2. Exactly two honest journeys

Autonomous means normal completion without routine operator intervention after a complete, enforceable preflight contract. Guided means one visible consequential decision at a time. Internal provider and runtime distinctions never become a hidden third journey.

## 3. Five-second operational truth

Every workspace answers: objective, phase, owner, reason, progress/evidence delta, blocker, next action, journey, memory influence, and comparison context. Urgent action outranks decorative analytics.

## 4. Logs are not evidence

Raw command/provider output begins as an Engagement Log Record. Parsing may create observations and candidates. Only provenance-bearing, policy-validated items become Verified Evidence. Findings require sufficient linked evidence or a separately audited operator override.

## 5. Unknown stays unknown

Topology, OSI layers, versions, CVE applicability, attack paths, and success claims are evidence-backed with confidence and conflicts. The product never fills a graph, metric, or report with invented completeness.

## 6. Explain failures as operational objects

`Blocked` is not an explanation. Every failed or blocked object records cause, originating component, last success, raw error reference, retry history, preserved progress/evidence, retryability, attempted recovery, impact, remediation, and valid next controls.

## 7. Deterministic supervision beats prompt hope

Progress signatures, action fingerprints, leases, heartbeats, retry taxonomy, budgets, circuit breakers, checkpoints, cancellation, and recovery are runtime mechanisms. Prompt advice supplements them but never substitutes for enforcement.

## 8. Registries are product data

Action classes, evidence types, deliverables, mission templates, agents, MCP tools, providers/models, failure categories, and policy readiness come from versioned runtime registries. React renders resolved capability; it does not maintain drifting lists.

## 9. The Brain must change behavior visibly

Every agent retrieves minimum relevant, scope-safe Context Packs at required lifecycle points. The operator can inspect which confirmed memory influenced wording, tool choice, plan, recovery, or report. If no relevant memory exists, the system records that fact instead of claiming to remember.

## 10. Memory is user-owned and class-separated

Preferences, operational knowledge, engagement memory, immutable evidence, and verified lessons have different scopes, lifecycles, retention, sensitivity, and approval rules. Users can confirm, correct, dispute, scope, expire, export, and forget. Credentials and raw confidential payloads never become reusable memory.

## 11. Obsidian is a projection, not a second truth

SQLite owns transactions. The Vault is a portable Markdown/YAML/wikilink projection and reviewed import surface with stable IDs, atomic writes, hashes, backups, conflict records, quarantine, and explicit filesystem permission.

## 12. Public models are untrusted external services

Local policy classifies and sanitizes every disclosure. Provider calls record model/prompt/context hashes, token/latency data, and exposure receipts. A verified local memory may still be forbidden from public disclosure.

## 13. Research improves strategy, never authority

The public LLM proposes one typed candidate. Local policy constrains it, disposable labs execute it, an immutable evaluator judges it, the Brain retains outcomes, and humans control promotion. Research cannot expand targets/actions, modify evaluators, see raw secrets, or self-deploy.

## 14. Semantic activity first

Primary feeds state what happened, why, what changed, evidence gained, and next action. Raw JSON, terminal output, request bodies, and provider events remain available in a sensitivity-controlled technical drawer.

## 15. Reliability outranks spectacle

Generated imagery, animation, graphs, and IDE/editor chunks are lazy and noncritical. Operational controls work offline, with media disabled, and under reduced motion. No fake progress, metrics, agents, logs, or topology ship in production paths.

## 16. Accessibility is interaction correctness

Every control has a semantic role/name, deterministic keyboard and pointer behavior, focus management, live status announcements, non-color cues, loading/error/disabled states, and a 44×44 target. Critical flows work at 200% zoom and on intentional mobile layouts.

## 17. Every control carries proof

An interaction is incomplete until it has a manifest entry, backend/state side effect, loading/error behavior, understandable copy, focus behavior, refresh/reconnect persistence, route reliability, and browser coverage in relevant states. Generated internal 404s are release blockers.

## 18. Parallel means isolated

Legacy remains operational and default. V2 has independent source, bundle, namespaces, API/events, database, artifacts, workers, quotas, and kill switch. A run has one server-enforced control plane and active state is never dual-written.

## 19. Cutover is a human decision

Passing source checks or rendering a page is not completion. Cutover requires zero known release-scope defects, complete interaction coverage, cross-browser/a11y/visual approval, migration/restart/backup/rollback proof, 72-hour soak, seven-day preview acceptance, legacy non-regression, and explicit sign-off.

## 20. Claims remain evidence-calibrated

The product and project reports distinguish implemented, tested, measured, pending, degraded, and unsupported. “Improved,” “verified,” “autonomous,” “connected,” and “complete” are used only when their defined evidence exists.
